# Inspectable course request details

The existing bounded original-blueprint call now requests a summary of eleven dimensions: subject, current level, desired depth, available time, target completion period, learning goals, preferred teaching methods, relevant prerequisites, desired assessments, project preferences and voluntarily stated accessibility preferences. Missing text details use `Not specified`; missing lists remain empty. The model is instructed to record only the submitted request and avoid inventing knowledge, time or disability facts. A model extraction can still be inaccurate; administrators must inspect it. No live extraction-quality benchmark was completed.

The server accepts five strings up to200 characters each and six lists with at most six strings of200 characters each, with an aggregate3500-character bound. Invalid types/lengths reject the blueprint/save; unknown fields are discarded. Older blueprints with no profile remain valid with `None` and show an explicit missing-details notice. This is request metadata, not a learner knowledge model or demonstrated mastery.

Administrators can edit the fields in the draft outline before generation. Read-only details remain visible afterward and in preserved lesson revisions. Native labeled fields display model/user text safely; lists use one entry per line in the editor. A shared workspace lock serializes outline saving with generation, scoring/review and lesson revision actions. Saves include the displayed revision and use an atomic draft-state/revision condition: stale saves or committed generation return409 without overwriting the outline. Errors preserve drafts; successful saves update the client revision. Legacy API clients without an expected revision remain accepted, but lack the new client's protection against already-stale drafts.

Original lesson prompts receive only the lesson specification plus saved request preferences. The prompt identifies both as untrusted data, disclaims verified mastery and stays within the existing supported lesson schema. UTF-8 input size is included in the existing token reservation; failed/oversized jobs preserve partial lessons and reservations. No stored student, account or evidence records are automatically attached. Explicit provider confirmation, institution/admin/feature restrictions and provider-contract configuration requirements remain in effect.

Curated beta continues to use its fixed reviewed foundations catalog. Administrators may save details for planning, but a visible notice states that these details do not change curated source selection or difficulty. Desired projects/assessments/preferences do not establish supported capabilities: the current graded course item remains a human-reviewed multiple-choice check. Free-text time/deadline preferences do not establish a validated completion schedule, workload estimate or calendar integration.

The profile persists inside the existing blueprint JSON, requiring no schema migration. Owner exports preserve it; the existing course account-deletion plan includes it. Tests verify recognized/unknown fields, invalid type/count/aggregate limits, old-blueprint compatibility, persistence, stale-save rejection, worker payload without account identity and export. Independent reviews verify privacy/budget boundaries and deferred-save/generation locking, draft preservation and revision updates. Real provider extraction accuracy, effective level/time adaptation and educational outcomes remain incomplete.
