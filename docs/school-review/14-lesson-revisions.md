# Preserved original-course revisions

An eligible administrator can revise one lesson in a completed original course. The lesson's revision controls offer manual editing of explanation, worked example, practice, common mistakes and delayed review, plus the question, existing options, correct-option selection and answer explanation. Required fields and server length/schema validation apply. The editor focuses its first field and keeps normal keyboard order. Invalid or failed saves preserve the draft.

Saving creates a separate course with copied content and new lesson IDs. It never overwrites the original course, lesson content, answer keys or evidence. The revision records its source course/lesson in blueprint metadata and exposes an original-course link. Every copied/edited lesson is unreviewed and the revised course requires another accuracy/key attestation before scoring. Builders' scores remain assisted; copying a check does not make it fresh independent evidence. Original and revised courses remain in owner export and are included in the existing account-deletion plan.

Regeneration requires administrator/flag/institution eligibility, generated-content permission, permitted/available provider and explicit provider confirmation. The new course copies all lessons except the selected one, then uses the existing worker to generate that missing key. One successful provider step saves it; the next step completes the job. Lease, cancellation, policy rechecks, reservation, retry and attempt limits remain in effect. Monthly reservations continue to use the owner/school/district ledger; a new course does not reset that ledger. The revision endpoint is limited to10 requests/hour. No live provider request was made in verification.

The source course must have all lessons saved and no queued/running generation. Curated courses cannot be rewritten through this original-content endpoint. Manual correction requires no provider request. Partial regeneration failure retains copied lessons and preserves the original. This uses existing additive course/lesson/job tables and introduces no schema migration. All returned/reviewed/exported lesson content follows blueprint prerequisite order, including a regenerated first lesson saved last.

During revision submission, a shared workspace lock disables fields and actions, preventing concurrent manual save/regeneration and edits that would otherwise be lost. Errors restore controls and preserve text; successful renders clear busy state. Delayed responses cannot replace a newer course selection or status. Native form controls keep technical JSON out of the editing flow.

Existing deletion coverage applies by owner. Read-only reviews caught and verified fixes for ordering, export order, concurrent actions and editor focus.
