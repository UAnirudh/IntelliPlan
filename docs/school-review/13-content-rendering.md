# Course content rendering

The saved explanation, worked example, practice, common mistakes and delayed review sections support Markdown paragraphs/lists/emphasis, tables, fenced code highlighting and inline/display math. Quiz questions/options/answer explanations, blueprint text and tutor replies retain their existing plain-text rendering. Images, embedded media and generated diagrams are not implemented. Math presentation does not execute or validate mathematical or programming assessments.

`static/js/learning_content.js` disables raw HTML, automatic linking and Markdown links/images. Explicit supported code languages are highlighted; unknown languages are escaped. Generated headings are scoped below the page/lesson headings. KaTeX uses `trust:false`, strict errors, fresh macros, maximum expansion1000 and maximum size10. Invalid math remains visible as escaped source. DOMPurify sanitizes the resulting fragment and additionally forbids active/link/media/form tags, URL attributes and IDs/names before DOM insertion. Reviewed catalog links remain separate fixed metadata.

Formatting accepts at most30000 characters per section,2000 per math expression and32 expressions per section. Missing dependencies, unsupported sanitization or parser failure show the original section as plain text with a visible fallback notice. These limits bound formatting work; they do not establish a universal hostile-input performance benchmark.

The libraries are self-hosted, with pinned versions, upstream licenses, package integrity and SHA256 file hashes in [the vendor manifest](../../static/vendor/learning-content/sources.json): markdown-it15.0.2, DOMPurify3.4.16, KaTeX0.19.0 and highlight.js11.12.0. No remote CDN is used. The vendor directory includes fonts and license files and adds about1.67MB to repository assets; fonts load when needed. The scripts/CSS are scoped to the hub. A production cold-cache/network performance comparison remains pending.

Primary implementation references: [markdown-it options](https://markdown-it.github.io/markdown-it/), [DOMPurify](https://github.com/cure53/DOMPurify), [KaTeX options](https://katex.org/docs/options.html), [KaTeX security](https://katex.org/docs/security.html) and [highlight.js](https://highlightjs.org/).

The complete run passes twelve HTTP/storage workflows, twenty-one responsive checks and twenty-one scoped axe audits with zero JavaScript errors.
