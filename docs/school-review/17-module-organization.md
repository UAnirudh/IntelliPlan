# Preserved course organization revisions

Administrators can change a completed course's title, overview, lesson titles, unit grouping, planned minutes, ordering and declared prerequisite edges. The editor uses native labeled fields, prerequisite checkboxes and keyboard-operable earlier/later buttons. A saved change creates an owner-scoped course revision; source content and scored evidence remain unchanged. Both curated and original courses are supported. Curated source text/media remains linked rather than ingested.

Every lesson key and objective must remain unchanged, as must course outcomes, prerequisites and request details. Changes to the teaching itself use the individual-lesson revision workflow. The normal blueprint validator requires unique lesson keys,5–120 integer minutes, and distinct string prerequisite keys occurring earlier in the sequence. Malformed dependency objects, cycles and invalid ordering return400. An administrator must explicitly adjust an edge when reorganizing its sequence; the server does not silently remove prerequisites.

The source must have every saved lesson and no queued/running generation job. Saves require the displayed revision; stale revisions return409. Owner, administrator, feature flag and institution checks apply; copying costs no provider call and queues no generation job. The endpoint is rate-limited10/hour. Copies receive new lesson IDs, carry no earlier scoring attempt, remain unreviewed, and require a new accuracy/prerequisite review before scoring. Builder scoring stays assisted. Duration edits are planning preferences, not validated scheduling estimates. Graph validity does not establish pedagogical quality or difficulty progression.

Owner learning exports now include lesson keys/IDs/review state alongside the existing flat content, and evidence lesson IDs/timestamps. This makes copied versus original results inspectable without changing the existing content keys. Export order follows the revised blueprint.
