# Phase 1 — Product + Technical Specification

## Product promise

> "I open IntelliPlan, and I immediately know exactly what I should do to succeed."

The student should never have to ask *"what should I work on?"* The application already knows.

The Command Center is the **single canonical surface** that answers this. Every existing dashboard/page becomes a deeper tab; the Command Center is the front door.

## Design constraints

1. **First contentful paint ≤ 1.5s on 4G mobile.** AI is never on the request path.
2. **Five-second comprehension rule.** Within 5 seconds of opening, the student can name their #1 task, why it matters, and how long it should take.
3. **Every number is explainable.** No score appears without a reason chip. Bad: "Health 72." Good: "Health 72 — down from 85 because of 2 overdue items and an exam in 3 days."
4. **Code computes, AI narrates.** Strict separation. Priority math, workload arithmetic, and health scoring are pure Python. AI is only invoked to produce voice + judgment on top of those facts.
5. **Additive only.** Do not modify existing `/dashboard`, `/live`, `/tasks/unified`, or any helper used by them. Ship `/command-center` and `/api/today` alongside.

## Surface composition

### 1. AI Briefing

2–4 sentences, present-tense, personal. Generated by the **Narrator** layer (Gemini Flash) from a fully-resolved facts payload. Cached in `BriefingCache`. Rendered the moment the page loads — the cache is the source of truth.

Example:

> "Good evening, Anirudh. Your chemistry test on Thursday is your highest-priority item this week — it's worth 25% of the unit and you currently have ~4.5 hours of work left for it. Starting tonight removes pressure from Wednesday, which is otherwise your heaviest day."

### 2. Today's Action Plan

Ordered list of 3–7 tasks. Each card shows:

- Title, course, due date
- **Priority score 0–100** + rationale chips (Urgency, Importance, Grade impact, Effort)
- Estimated time, energy fit, deadline
- One-line "why now" produced by the Narrator

### 3. Workload Forecast

Bar chart of projected work hours by day for the next 7 days, with the "heaviest day" called out. Stress level computed from available hours vs. estimated workload.

### 4. Academic Health Score

0–100 with a delta vs. yesterday and a 1-sentence reason. Components:

- Missing assignments (–)
- Upcoming high-stakes items (–)
- Grade trend (±)
- Completion rate (+)
- Schedule balance (+)

```
├──────────────────────────────────────────────────────────┤
│ Intelligence                                             │
│   PriorityEngine    — 0–100 score, structured rationale  │
│   WorkloadForecaster — hours/day for next 7 days         │
│   HealthScore       — 0–100 + reasons                    │

├──────────────────────────────────────────────────────────┤

```

### Code-handles-facts vs. AI-handles-judgment

| Code (pure Python, deterministic, unit-tested) | AI (Gemini Flash via `ai_provider`) |
|---|---|
| Days until due | Briefing voice and tone |
| Priority score | "Why now" one-liner per task |
| Workload hours/day | Strategy paragraph (e.g. "split into 2 sessions") |
| Health score + deltas | Encouragement / nudge framing |
| Schedule slot availability | Trade-off explanations between competing priorities |
| Grade impact arithmetic | Personalized study technique recommendations |

### Priority score — the algorithm

`priority.compute(assignment, context) → PriorityScore`

```
score = urgency_score   (0..40)
      + importance_score(0..25)
      + grade_impact_score(0..20)
      + effort_score    (0..10)
      + dependency_score(0..5)
```

Components (deterministic):

- **Urgency (0..40)** — piecewise function of `days_until_due`:
  `overdue → 40`, `due today → 38`, `tomorrow → 34`, `+2d → 28`, `+3d → 22`, `+5d → 14`, `+7d → 8`, else `4` if status is "not started" else `2`.
- **Importance (0..25)** — assessment-type weight:
  exam/final = 25, project/essay = 20, quiz/test = 15, lab = 12, homework = 8, classwork = 5, other = 4. Detected by regex over title (current `_BIG_TITLE_RE` extended).
- **Grade impact (0..20)** — `min(20, round(20 * points_possible / max_points_in_class))` when course max is known, else fall back to `points_possible` brackets (≥80 → 18, ≥30 → 12, else 6).
- **Effort (0..10)** — short tasks (<30min est.) bonus when due soon, big tasks (>2h est.) bonus when not yet started. Encourages momentum.
- **Dependency (0..5)** — +5 if the task is prereq for an upcoming exam in same course (e.g. "review guide" before "test").

Each component returns both the score and a one-line reason. The full `PriorityScore.rationale` is a `list[ReasonChip]` rendered next to the number — this is what makes the number explainable.

### Workload forecast — the model

`workload.forecast(assignments, availability, today) → list[DayLoad]` for the next 7 days.

For each day `d`:

- `committed_hours_d` = estimated minutes for any task with `due_date == d` not yet complete.
- `pre_work_d` = portion of upcoming-but-not-due tasks recommended to land on day `d`, distributed backwards from `due_date` using a greedy fill against `availability_d`.
- `stress_d = max(0, committed_hours_d + pre_work_d - available_hours_d)`.

`heaviest_day = argmax(committed + pre_work)`. Tomorrow's stress drives the briefing nudge ("starting tonight reduces Thursday by 35%").

### Academic Health Score — the model

`health.compute(snapshot) → HealthScore`, range 0..100.

```
base                  = 100
- 8 per overdue item
- 4 per high-stakes item due in ≤ 3 days with no progress
- 6 per failing course (current grade < 70%)
- 4 per declining-trend course (last 3 grades trending down ≥ 5 pts)
+ 5 if completion_rate_7d ≥ 0.8
+ 5 if schedule_balance_index ≥ 0.6
clamp to [0, 100]
```

`HealthScore.deltas` is the per-component diff vs. yesterday's cached snapshot. Stored daily in `HealthSnapshot` (new table — see Phase 2).

### Narrator — the AI layer

Single function: `narrator.brief(payload: TodayPayload) → BriefingText`.

- Always called against fully-resolved facts. No SQL. No date math.
- Prompt is a structured JSON dump of: today's top 3 tasks (with rationale chips), the heaviest day, the health delta, the student's identity (grade level, focus areas, goals), and the last completed session.
- Output schema enforced via `ai_chat_json` (already exists in `ai_provider.py`).
- Caches result in `BriefingCache(user_id, payload_hash, generated_at, text_json)`. Reuses when `payload_hash` is unchanged and `generated_at < 6h ago`.
- Falls back to a templated briefing built from the same facts when AI is unavailable — the Command Center degrades gracefully, never blank.

## Non-goals for the Command Center MVP

- No native mobile app changes.
- No new LMS integrations.
- No multi-user / group / live-session work.
- No re-skin of existing pages.
- No deletion or rewrite of any existing route or model.
- No Alembic migration — schema additions use the existing `apply_study_schema_migrations` pattern *just for the new tables*, with the deprecation noted.

## What success looks like

- `/command-center` renders the briefing, plan, forecast, and health in one HTML response in <1.5s on 4G.
- The plan list, when given the same input snapshot, produces the **same ordering across runs** — no AI randomness in ordering.
- Every score on the page is hoverable / tappable for its rationale.
- The page works fully without JS (briefing + plan render server-side); HTMX/Alpine progressively enhance interactions.
